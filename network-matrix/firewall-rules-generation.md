# Firewall rules generation

The network communication matrix (`network-matrix/network-communication-matrix.md`) is the source of truth. This file converts it into firewall rules per host role.

## Approach

Rules are generated from the matrix, not hand-written. Two implementations:

| Implementation | Use | Notes |
|---|---|---|
| nftables (Ubuntu, Oracle Linux 9) | Default | Declarative, scriptable, testable |
| firewalld (Oracle Linux 8/9 default) | Alternative | Zone-based; needs a dedicated zone with rich rules |

Rules are generated by Ansible from a structured copy of the matrix, so the matrix and the firewall cannot drift silently. The generator writes a checksum of the matrix into the ruleset; a mismatch fails the run.

## nftables ruleset skeleton

```nft
#!/usr/bin/nft -f

flush ruleset

table inet filter {
    set mgmt_hosts {
        type ipv4_addr
        flags interval
        elements = { 10.10.0.0/24 }
    }
    set cp_hosts {
        type ipv4_addr
        flags interval
        elements = { 10.20.0.0/24 }
    }
    set storage_hosts {
        type ipv4_addr
        flags interval
        elements = { 10.40.0.0/24 }
    }
    set dns_servers {
        type ipv4_addr
        elements = { 10.10.0.10 }
    }
    set ntp_servers {
        type ipv4_addr
        elements = { 10.10.0.11 }
    }

    chain input {
        type filter hook input priority 0; policy drop;

        ct state established,related accept
        iif "lo" accept

        # SSH from the management segment only
        ip saddr @mgmt_hosts tcp dport 22 accept

        # DNS and NTP from the node to the internal resolvers
        ip daddr @dns_servers udp dport 53 accept
        ip daddr @dns_servers tcp dport 53 accept
        ip daddr @ntp_servers udp dport 123 accept

        # Kubernetes API: only from the control-plane segment and the
        # management segment (automation server, monitoring, CI)
        ip saddr @cp_hosts tcp dport 6443 accept
        ip saddr @mgmt_hosts tcp dport 6443 accept

        # etcd: only from control-plane nodes
        ip saddr @cp_hosts tcp dport { 2379, 2380 } accept

        # kubelet
        ip saddr @cp_hosts tcp dport 10250 accept
        ip saddr @mgmt_hosts tcp dport 10250 accept

        # node_exporter
        ip saddr @mgmt_hosts tcp dport 9100 accept

        # Ceph public network (MON/OSD/MDS/RGW) from the storage segment
        ip saddr @storage_hosts tcp dport { 6789, 6800-7568, 7480 } accept

        # GPU DCGM exporter
        ip saddr @mgmt_hosts tcp dport 9400 accept

        # Log shipping
        ip saddr @mgmt_hosts tcp dport { 3100, 5044, 9200 } accept

        # Rate limit the rest of the noise before logging
        limit rate 10/second burst 20 packets accept
        log prefix "nft-drop " level info limit rate 5/minute
    }

    chain forward {
        type filter hook forward priority 0; policy drop;
        ct state established,related accept
    }

    chain output {
        type filter hook output priority 0; policy accept;
    }
}
```

## Role-specific rules

The base ruleset is shared; each role adds or removes specific ports.

| Role | Adds | Removes |
|---|---|---|
| Control plane | 6443 in from mgmt+cp, 2379/2380 from cp | — |
| Worker | 10250 from cp+mgmt, 30000-32767 only if NodePort is used | 6443 in (workers do not serve the API) |
| Storage node | 6800-7568, 6789, 7480 from storage | — |
| GPU node | 9400 from mgmt | — |
| Management cluster | 443 from dmz | — |
| DMZ edge | 443 from outside | everything else |

## Implementation in Ansible

```yaml
# ansible/roles/firewall/tasks/main.yml
- name: Render the nftables ruleset
  ansible.builtin.template:
    src: nftables.conf.j2
    dest: /etc/nftables.conf
    mode: "0600"
  vars:
    matrix_checksum: "{{ matrix_data | to_json | hash('sha256') }}"

- name: Validate the ruleset
  ansible.builtin.command: nft --check -f /etc/nftables.conf
  changed_when: false

- name: Reload nftables
  ansible.builtin.systemd:
    name: nftables
    state: reloaded
```

`nft --check` runs before the reload. A ruleset that fails to parse is never installed.

## firewalld alternative (Oracle Linux)

```bash
firewall-cmd --permanent --new-zone=cloud-node
firewall-cmd --permanent --zone=cloud-node --add-source=10.10.0.0/24
firewall-cmd --permanent --zone=cloud-node --add-port=22/tcp
firewall-cmd --permanent --zone=cloud-node --add-port=6443/tcp
firewall-cmd --reload
```

Use one implementation, never both. Two active firewalls produce rulesets that neither administrator fully understands.

## Validation

```bash
# From an allowed host
nmap -Pn -p 22,6443,2379,2380,10250,9100 <target>

# From a denied host
nmap -Pn -p 22,6443,2379,2380,10250,9100 <target>
# Expect: filtered

# Ruleset loaded?
nft list ruleset
firewall-cmd --list-all
```

Both results are recorded as evidence for acceptance test B-10.

## Maintenance

- Regenerate from the matrix on every matrix change. Do not hand-edit a host's ruleset.
- Keep a per-environment override layer in `site-<env>` for site-specific exceptions, so the base matrix stays clean.
- Review the dropped-packet log before changing anything. The log tells you what the traffic actually needs.
